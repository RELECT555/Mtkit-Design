# Select tools for the task

At first use in an application project, call MTKit Catalog's `bootstrap_project` for the current client unless setup has already been checked in this session. During authorized onboarding, apply its managed instruction block with the client's file tools, preserving existing rules, then reread the file to verify the result. For a review-only or read-only task, use its guidance in-session and report that setup was not persisted. The server returns a plan and cannot write the application's files itself.

At the start of a frontend task, call `recommend_tools` with `task` set to a short summary of the requested outcome and relevant stack. Include constraints that affect the choice, such as review only, a supplied mockup, or keyboard testing. Keep private source, credentials, and internal URLs in the project.

Use recommendations that fit the request and are available in the current client. Read the selected installed skills before applying them. If a skill is not installed, use `get_skill` with its catalog ID to read its instructions; use the optional `path` for Markdown references within that skill. Reading instructions does not install their helper scripts. Call the relevant configured MCP tools when the work calls for them, after checking that the client actually exposes those tools. Bundled means included in the plugin, not currently connected. Keep any review-only restriction and preserve the installed MTKit version and API. If a missing runtime, helper or MCP blocks the task, explain the gap and request its `plan_install` for the current client. Treat the result as setup instructions and follow the user's scope for installation.

Reuse recommendations already obtained for the same task when following another workflow. If MTKit Catalog is unavailable or returns no useful recommendation, select relevant installed skills using the [frontend skill guide](frontend-skills.md) and continue with the tools available in the client.
