# Как работать с MTKit Design

Открой рабочий проект в агенте и начни новый чат после подключения MTKit Catalog. Опиши, что нужно сделать, где и как проверить результат. Агент может передать задачу в MTKit Catalog через `recommend_tools` и получить подходящие навыки и MCP-серверы. Если в клиенте доступно несколько наборов, можно добавить к задаче «Используй MTKit Design». [Установка плагина и подключение MCP](../README.md#установка-плагина-codex)

В Codex основной набор доступен через плагин. При отдельном подключении MCP каталог подбирает инструменты, отдаёт инструкции навыка через `get_skill` и показывает план установки. Агент читает выбранную инструкцию и выполняет задачу с доступными ему инструментами. Пометка «в комплекте» означает состав плагина, а доступность конкретного MCP нужно проверить в текущем клиенте. Чтение навыка не устанавливает его вспомогательные скрипты.

Собственные инструкции MTKit встроены в сервер. Для чтения внешних навыков серверу нужен доступ к `raw.githubusercontent.com`; используется закреплённая ревизия источника. Установленные навыки можно читать локально. Если нужен helper на Python или дополнительный MCP, агент проверяет зависимости и сообщает о недостающих. [Проверки и ограничения](mcp-readiness.md)

Правила подбора теперь создаются при настройке проекта. Для Codex используйте установщик с `--project "путь/к/приложению"`: он подключит плагин и добавит блок MTKit в `AGENTS.md`, сохранив остальные инструкции. Для уже подключённого MCP доступна команда `node scripts/setup-project.mjs --project "путь/к/приложению" --client codex` из репозитория MTKit Design. Для других клиентов замените `codex` на `claude-code`, `cursor` или `vscode`. [Автоматическая настройка проекта](agent-project-rules.md)

При подключении только по URL MCP предлагает агенту вызвать `bootstrap_project` и записать правила в рабочий проект. Запись выполняет агент с разрешениями своего клиента. Если разрешена только работа без изменений, он применяет правила в текущем сеансе и отмечает, что они ещё не сохранены. После настройки в обычных задачах достаточно описывать желаемый результат; перечислять навыки вручную не требуется.

## Проверить подключение

```text
Проверь, подключён ли MTKit Catalog. Покажи категории и количество инструментов. Если каталог недоступен, объясни, что проверить.
```

В истории инструментов найди ответ сервера. Для диагностики можно явно попросить `list_categories`. Если вызова нет, проверь подключение MTKit Catalog в клиенте. Для командного URL проверь доступ из корпоративной сети или VPN и наличие `MTKIT_MCP_TOKEN` в окружении клиента. После изменения конфигурации открой новый чат. [Проверка командного подключения](deploy-mcp.md#4-проверить-и-передать-команде)

## Найти инструмент

```text
Подбери инструменты для проверки React-интерфейса в браузере. Нужно проверить мобильную вёрстку и управление с клавиатуры. Объясни, что выбрать, и покажи шаги подключения для Codex. Пока только покажи план.
```

Для другого клиента замени Codex в запросе на Claude Code, Cursor или VS Code с Copilot. Если инструмент уже доступен, можно сразу попросить агента выполнить проверку.

## Сделать экран

```text
Сделай экран поставщиков в мини-CRM на маршруте /suppliers. Менеджер должен найти поставщика и добавить нового. Используй React, TypeScript и компоненты @mtkit/ui. Сохрани тему проекта, учти загрузку, пустой список и ошибку. Проверь основной сценарий на десктопе и телефоне.
```

Для своей задачи укажи маршрут, главное действие пользователя, обязательные состояния и, если есть, приложи макет или ссылку на похожий экран.

## Проверить интерфейс

```text
Проверь экран /suppliers. Убедись, что менеджер может найти поставщика и добавить нового на десктопе, телефоне и с клавиатуры. Проведи только ревью. Для каждой проблемы укажи шаги воспроизведения и отметь, что подтвердил в браузере.
```

Укажи реальный маршрут или локальный URL. Для ревью нужен запущенный проект и доступный агенту браузер. В истории инструментов можно проверить, что агент вызвал `recommend_tools` и какие рекомендации вернул каталог.
